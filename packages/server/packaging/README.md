# Nex server single binary (SEA)

`node scripts/build-sea.mjs` produces a self-contained Node single executable
(SEA, Single Executable Application) with the full agent runtime embedded
(`nex.cjs` + playwright/koffi/official plugins/bundled skills/runtime tools),
reusing the same asset collectors and release mechanism as the CLI SEA.

## Artifacts

| File | Platform |
| --- | --- |
| `dist/sea/nex-server-darwin-arm64` | macOS Apple Silicon |
| `dist/sea/nex-server-linux-x64` | Linux x86_64 |
| `dist/sea/nex-server-linux-arm64` | Linux arm64 |

One binary, two roles (`src/seaEntry.ts`):

```bash
./nex-server            # HTTP server (default, equivalent to node dist/entry-http.js)
NEX_SEA_AGENT_ROLE=1 ./nex-server app-server --stdio   # agent role (spawned by the server itself)
```

On startup the server releases the embedded `nex.cjs` into
`$NEX_DATA_BASE_DIR/sea-agent/<fingerprint>/` (falling back to the user cache
without a data dir: `~/Library/Caches/nex/sea-agent`, `~/.cache/nex/sea-agent`)
and points the agent command back at the binary itself via the
`NEX_AGENT_SERVER_COMMAND` env override.

## Build

```bash
# 0) Prerequisites: workspace package dist files (generated by typecheck)
#    and the agent bundle
pnpm typecheck
pnpm -r --filter "@nex/cli..." build

# 1) Build (the host platform's smoke test runs automatically: HTTP role
#    starts the server, agent role runs --version)
node scripts/build-sea.mjs                     # all three platforms
node scripts/build-sea.mjs --target linux-x64  # single target (cross builds skip the node download)

# The Node version used for the build must match the license entry recorded in
# third-party/runtime/sources.json (currently 24.14.0, see apps/nex-cli engines).
# On mismatch, provide the binary explicitly:
node scripts/build-sea.mjs --node-binary darwin-arm64=/path/to/node-v24.14.0/bin/node
```

## Install as a system service

See `packaging/`: `install.sh` (supports `--uninstall`) + `nex-server.service`
(systemd) + `com.nex.server.plist` (launchd). After install, the token lives in
`/etc/nex-server/env` on Linux and `~/.nex/server-data/env` on macOS.

```bash
sudo ./packaging/install.sh --binary ./dist/sea/nex-server-linux-x64
```
